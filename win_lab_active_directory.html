Domein, AD en LDAP
Theorie 01
Active Directory en LDAP begrijpen
theorie
›

Active Directory (AD) is het centrale beheersysteem van Microsoft voor een domein. Het slaat alle gebruikers, computers, policies en configuraties op in de database NTDS.dit.

LDAPLightweight Directory Access Protocol — het protocol waarmee clients en diensten gegevens uit AD opvragen. LDAP gebruikt een hiërarchische boomstructuur (Distinguished Names).

Voorbeelden van LDAP-gebruik:

  • NAS-opslag die AD-gebruikers authenticateert
  • Wi-Fi accesspoints die via LDAP koppelen aan AD
  • Applicaties die AD-groepen gebruiken voor rechtenbeheer
TermBetekenis
NTDS.ditDe AD-database — bevat alle domeinobjecten
DCDomain Controller — server die AD host
DNDistinguished Name — volledig pad van een AD-object
OUOrganizational Unit — container voor objecten in AD

Geef de server de correcte naam vóór je AD installeert.

Taak 04
AD DS-rol installeren
installatie
›

Installeer de Active Directory Domain Services-rol via Server Manager.

  • Open Server Manager
  • Manage → Add Roles and Features
  • Role-based installation → Next
  • Selecteer je server → Next
  • Vink aan: Active Directory Domain Services
  • Voeg de bijhorende features toe (DNS Server wordt automatisch voorgesteld)
  • Next → Next → Install
✔ VerificatieNa installatie zie je een gele waarschuwing in Server Manager: "Promote this server to a domain controller".
Taak 05
Server promoveren tot Domain Controller
config
›

Klik op de promotieboodschap in Server Manager om de wizard te starten.

  • Kies: Add a new forest
  • Root domain name: pxldigital.local
  • Forest/Domain functional level: Windows Server 2016 of hoger
  • Vink aan: DNS Server, Global Catalog
  • Stel een DSRM-wachtwoord in (Recovery Mode — bewaar dit goed!)
  • NetBIOS-naam wordt automatisch ingevuld: PXLDIGITAL
  • Paths: laat standaard → Next → Install
⚠ Let op — De server herstart automatisch na promotie. Na herstart log je in met PXLDIGITAL\Administrator.
✔ VerificatieOpen Active Directory Users and Computers — je ziet de domeinstructuur.
OU, Users en Groups
Taak 06
Organizational Units aanmaken
config
›

OUs structureren je AD-omgeving. Maak de basisstructuur aan:

  • Open Active Directory Users and Computers (ADUC)
  • Rechtsklik op pxldigital.local → New → Organizational Unit
  • Maak aan: pxldigital
  • Binnen pxldigital maak je: Users, Groups, Computers
  • Binnen Users maak je: Lectoren, Studenten
Waarom OUs?OUs laten toe om GPOs toe te wijzen aan specifieke groepen gebruikers of computers. Elke OU kan zijn eigen policy krijgen.
Taak 07
Gebruikers en groepen aanmaken
config
›

Maak testgebruikers en security groups aan.

Gebruikers aanmaken:

  • Rechtsklik op de OU Lectoren → New → User
  • Vul in: First name, Last name, User logon name (formaat: voornaam.achternaam)
  • Wachtwoord instellen → vink "Password never expires" aan voor het lab
  • Herhaal voor een student in de OU Studenten

Security groups aanmaken:

  • Rechtsklik op de OU Groups → New → Group
  • Group name: GL_Lectoren, Scope: Global, Type: Security
  • Maak ook: DL_FileShare_Lezen, Scope: Domain Local
✔ VerificatieControleer in ADUC dat de gebruikers en groepen zichtbaar zijn in de juiste OUs.

Vereisten op de server:

  • Statisch IP-adres ingesteld
  • DNS verwijst naar zichzelf (localhost / 127.0.0.1)

Vereisten op de client (WINADV-PC1):

  • Naam gewijzigd naar WINADV-PC1
  • Statisch IP in hetzelfde subnet als de DC
  • DNS-server ingesteld op IP van de DC

Joinen:

  • Settings → System → About → "Domain or workgroup"
  • Klik "Change" → selecteer Domain → vul in: pxldigital.local
  • Gebruik de Administrator-credentials van het domein
  • Je krijgt "Welkom bij het domein pxldigital.local" → OK → Restart

AGDLP
Theorie 10
AGDLP-model begrijpen en toepassen
theorieconfig
›

AGDLP staat voor: Accounts → Global groups → Domain Local groups → Permissions

Waarom AGDLP?Dit is de Microsoft best-practice voor rechtenbeheer. Door accounts in global groups te steken en die aan domain local groups te koppelen, kun je rechten centraal beheren zonder individuele gebruikers te moeten wijzigen.

Voorbeeld voor klaslokalen:

Accounts (studenten) → GL_1SNEA (global) → DL_1SNEA (domain local) → Permissie op map
StapActieVoorbeeld
AGebruikersaccounts aanmakenstudent1, student2
GGlobal Group aanmaken en vullenGL_1SNEA (bevat student1, student2)
DLDomain Local Group aanmakenDL_1SNEA (bevat GL_1SNEA)
PPermissie toewijzen op resourceMap "Klassen" → DL_1SNEA: Read
ℹ Info — Door nesting kun je meerdere Global Groups aan één Domain Local Group koppelen. Ideaal voor afdelingen met subgroepen.
