DNS
Theorie 01
DNS-recordtypes en zones begrijpen
theorie
›

DNS vertaalt namen naar IP-adressen (en omgekeerd). Op een Windows DC draait DNS automatisch mee als AD-geïntegreerde service.

RecordtypeFunctieVoorbeeld
ANaam → IPv4-adrestop.pxldigital.local → 7.7.7.7
AAAANaam → IPv6-adresweb → 2001:db8::1
CNAMEAlias → andere naamDC1 → winadv-dc1jb.pxldigital.local
PTRIP → naam (reverse)10.10.10.1 → winadv-dc1jb
MXMailserver van een domeinpxldigital.local → mail.pxldigital.local
NSNameserver van een zonepxldigital.local → winadv-dc1jb
Forward vs. Reverse zonesEen forward lookup zone vertaalt namen naar IPs. Een reverse lookup zone doet het omgekeerde (IP → naam) via PTR-records, en is genoemd naar het subnet in omgekeerde volgorde: 10.10.10.x → zone 10.10.10.in-addr.arpa.

Testen doe je met nslookup of het modernere PowerShell-commando:

Resolve-DnsName top.pxldigital.local
Taak 02
A-record toevoegen (top.pxldigital.local → 7.7.7.7)
config
›

Via de GUI:

  • Open DNS Manager (Server Manager → Tools → DNS)
  • Forward Lookup Zones → pxldigital.local
  • Rechtsklik → New Host (A or AAAA)
  • Name: top → IP address: 7.7.7.7 → Add Host

Via PowerShell:

Add-DnsServerResourceRecordA -ZoneName "pxldigital.local" -Name "top" -IPv4Address "7.7.7.7"

Lookup testen:

Resolve-DnsName top.pxldigital.local
✔ VerificatieDe lookup geeft 7.7.7.7 terug als A-record.
Taak 03
Aliassen DC1 en DC2 aanmaken (CNAME)
config
›

Maak twee aliassen die verwijzen naar je eerste en tweede AD-server.

AliasVerwijst naar
DC1.pxldigital.localWINADV-DC1XX.pxldigital.local (eerste DC)
DC2.pxldigital.localWINADV-DD2.pxldigital.local (tweede DC)

Via de GUI:

  • DNS Manager → Forward Lookup Zones → pxldigital.local
  • Rechtsklik → New Alias (CNAME)
  • Alias name: DC1 → FQDN of target host: WINADV-DC1XX.pxldigital.local
  • Herhaal voor DC2 → WINADV-DD2.pxldigital.local

Via PowerShell:

Add-DnsServerResourceRecordCName -ZoneName "pxldigital.local" -Name "DC1" -HostNameAlias "WINADV-DC1XX.pxldigital.local" Add-DnsServerResourceRecordCName -ZoneName "pxldigital.local" -Name "DC2" -HostNameAlias "WINADV-DD2.pxldigital.local"

Lookup testen:

Resolve-DnsName DC1.pxldigital.local Resolve-DnsName DC2.pxldigital.local
✔ VerificatieBeide lookups tonen het CNAME-record én het onderliggende A-record van de juiste DC.
Taak 04
Nieuwe zone xx.local aanmaken met records
config
›

Maak een nieuwe forward lookup zone aan met je initialen, bijv. jb.local, en voeg er twee records aan toe.

Zone aanmaken via de GUI:

  • DNS Manager → rechtsklik op Forward Lookup Zones → New Zone
  • Zone type: Primary zone (AD-integrated mag aangevinkt blijven)
  • Zone name: jb.local (jouw initialen)
  • Volg de wizard verder met de standaardinstellingen

Via PowerShell:

Add-DnsServerPrimaryZone -Name "jb.local" -ReplicationScope "Domain"

Records toevoegen:

RecordTypeWaarde
winadvA1.1.1.1
rulesCNAMEverwijst naar winadv.jb.local
Add-DnsServerResourceRecordA -ZoneName "jb.local" -Name "winadv" -IPv4Address "1.1.1.1" Add-DnsServerResourceRecordCName -ZoneName "jb.local" -Name "rules" -HostNameAlias "winadv.jb.local"

Resolve testen:

Resolve-DnsName winadv.jb.local Resolve-DnsName rules.jb.local
✔ Verificatiewinadv.jb.local resolvet naar 1.1.1.1, en rules.jb.local volgt de alias naar hetzelfde adres.
Taak 05
DNS forwarders configureren (8.8.8.8 en 1.1.1.1)
config
›

Een forwarder is de DNS-server waarnaar jouw server vragen doorstuurt die hij zelf niet kan beantwoorden (alles buiten je eigen zones).

Via de GUI:

  • DNS Manager → rechtsklik op de servernaam → Properties
  • Tabblad Forwarders → Edit
  • Voeg toe: 8.8.8.8 (Google) en 1.1.1.1 (Cloudflare)

Via PowerShell:

Set-DnsServerForwarder -IPAddress 8.8.8.8, 1.1.1.1

Controleren:

Get-DnsServerForwarder
ℹ Volgorde telt — De server probeert forwarders in volgorde. Pas als de eerste niet antwoordt, gaat hij naar de tweede.
Taak 06
Reverse lookup zone aanmaken
config
›

Maak een reverse lookup zone aan voor het subnet van pxldigital.local zodat IP-adressen terug naar namen vertaald kunnen worden.

Via de GUI:

  • DNS Manager → rechtsklik op Reverse Lookup Zones → New Zone
  • Zone type: Primary zone → IPv4 Reverse Lookup Zone
  • Network ID: vul je subnet in, bijv. 10.10.10
  • Volg de wizard verder met de standaardinstellingen

Via PowerShell:

Add-DnsServerPrimaryZone -NetworkId "10.10.10.0/24" -ReplicationScope "Domain"

PTR-records: bestaande A-records krijgen niet automatisch een PTR. Vink bij nieuwe A-records "Create associated pointer (PTR) record" aan, of voeg ze manueel toe:

Add-DnsServerResourceRecordPtr -ZoneName "10.10.10.in-addr.arpa" -Name "1" -PtrDomainName "WINADV-DC1XX.pxldigital.local"

Reverse lookup testen:

Resolve-DnsName 10.10.10.1
✔ VerificatieDe reverse lookup van het IP-adres geeft de hostnaam van de server terug.
DHCP
Taak 07
DHCP-rol installeren op de eerste DC
installatie
›

Via de GUI:

  • Server Manager → Manage → Add Roles and Features
  • Vink aan: DHCP Server → Add Features → Install
  • Na installatie: klik op de gele waarschuwing → Complete DHCP configuration
  • Dit autoriseert de DHCP-server in Active Directory

Via PowerShell:

Install-WindowsFeature DHCP -IncludeManagementTools

Autoriseren in AD:

Add-DhcpServerInDC -DnsName "WINADV-DC1XX.pxldigital.local"
Waarom autorisatie?In een AD-omgeving moet elke DHCP-server geautoriseerd zijn. Dit voorkomt dat een rogue DHCP-server in het netwerk foute IP-configuraties uitdeelt.
Taak 08
DHCP-scope aanmaken (x.x.x.200 – x.x.x.250)
config
›

Maak een scope aan voor je huidige subnet. De range loopt van x.x.x.200 tot x.x.x.250 (vervang x.x.x door jouw subnet, bijv. 10.10.10). De lease moet ook de domeinnaam, DNS en gateway meegeven.

Via de GUI:

  • Server Manager → Tools → DHCP
  • Vouw de server open → rechtsklik op IPv4 → New Scope
  • Name: bijv. Scope-Intern
  • IP range: 10.10.10.200 t/m 10.10.10.250, subnet mask 255.255.255.0
  • Router (gateway): jouw gateway-adres
  • DNS server: IP van je DC → Parent domain: pxldigital.local
  • Activate scope: Yes

Via PowerShell:

Add-DhcpServerv4Scope -Name "Scope-Intern" -StartRange 10.10.10.200 -EndRange 10.10.10.250 -SubnetMask 255.255.255.0 -State Active

Scope-opties instellen (DNS, gateway, domeinnaam):

Set-DhcpServerv4OptionValue -ScopeId 10.10.10.0 -DnsServer 10.10.10.1 -Router 10.10.10.254 -DnsDomain "pxldigital.local"
✔ VerificatieIn de DHCP-console staat de scope met een groen icoon (actief). Scope Options tonen optie 003 (Router), 006 (DNS) en 015 (Domain Name).
Taak 09
Client IP laten ophalen via DHCP
configtest
›

Zet de client om van statisch IP naar DHCP zodat hij voortaan zijn adres van de DHCP-server krijgt.

Via de GUI (op de client):

  • Settings → Network & Internet → Ethernet → IP assignment → Edit
  • Zet op Automatic (DHCP)

Via PowerShell (op de client, als admin):

Set-NetIPInterface -InterfaceAlias "Ethernet0" -Dhcp Enabled Set-DnsClientServerAddress -InterfaceAlias "Ethernet0" -ResetServerAddresses

Lease vernieuwen en controleren:

ipconfig /release ipconfig /renew ipconfig /all
✔ VerificatieIn ipconfig /all: "DHCP Enabled: Yes", een IP in de range .200–.250, en de juiste DNS/gateway/DNS-suffix. Op de server verschijnt de lease onder Address Leases.
Taak 10
Tweede scope aanmaken (10.11.12.0/24)
config
›

Maak een tweede scope aan met de volgende instellingen:

InstellingWaarde
Subnet10.11.12.0/24
DNS10.11.12.2
Gateway10.11.12.254
Domainjb.local (jouw initialen — de zone uit Taak 04)

Via PowerShell:

Add-DhcpServerv4Scope -Name "Scope-JB" -StartRange 10.11.12.1 -EndRange 10.11.12.250 -SubnetMask 255.255.255.0 -State Active
Set-DhcpServerv4OptionValue -ScopeId 10.11.12.0 -DnsServer 10.11.12.2 -Router 10.11.12.254 -DnsDomain "jb.local"

Alle scopes controleren:

Get-DhcpServerv4Scope Get-DhcpServerv4OptionValue -ScopeId 10.11.12.0
ℹ Meerdere scopes — Een DHCP-server bedient maar één scope per fysiek netwerksegment. Een tweede scope wordt pas relevant met een DHCP-relay of een tweede interface in dat subnet — voor dit lab volstaat de configuratie zelf.
