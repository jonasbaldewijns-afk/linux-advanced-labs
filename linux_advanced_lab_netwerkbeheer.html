PXL Linux Advanced · Netwerkbeheer Lab

Netwerkbeheer

Hands-on labo: netwerkdiagnose, NetworkManager met nmcli, statische configuratie, netwerk bonding voor redundantie, en de server als router met PAT/masquerading. Werk op je RHEL/Rocky VMs.

📋 Scenario

Je beheert een server met twee netwerkkaarten. De eerste interface (ens160) gaat naar het externe NAT-netwerk (internet), de tweede (ens224) bedient een afgeschermd intern netwerk waar je client op zit. Je moet IP-adressen statisch instellen, redundantie voorzien via bonding, en de server laten functioneren als router zodat de client via de server het internet bereikt.

🗺 Netwerktopologie

▣ SERVER
ens160 192.168.112.100/24
→ NAT / internet · gw .2
ens224 10.10.10.1/24
→ intern netwerk · router
◄── vmnet10 ──►
▢ CLIENT
ens160 10.10.10.10/24
→ gw 10.10.10.1 (server)
Bereikt internet via de server

Deel 1 — Netwerkdiagnose & Tools
Tools Taak 01
Bekijk je netwerkinterfaces met ip a
▶

Op de server: het moderne commando om interfaces te bekijken is ip. De oudere ifconfig bestaat nog maar is verouderd.

# Moderne manier (volledige + verkorte vorm) ip addr show ip a # Oude manier (verouderd, soms niet geïnstalleerd) ifconfig ens160
💡 Begrijp dit Let in de output op: het IP-adres (inet), het MAC-adres (ether/link), en de status (UP/DOWN). Een interface kan UP zijn maar toch geen IP hebben — dat zijn twee aparte dingen.
✔ Verificatie Je ziet minstens lo (loopback) en ens160. Welk IP heeft ens160? Welk MAC-adres?
Tools Taak 02
Test connectiviteit en analyseer je routes
▶

Drie klassieke diagnose-commando's: ping test bereikbaarheid, route/ip route toont waar verkeer heen gaat, traceroute toont het volledige pad.

# Ping de gateway 4 keer ping -c 4 192.168.112.2 # Toon de routeringstabel (numeriek, toont echte gateway-IP) route -n ip route show # Toon het volledige pad naar een host traceroute www.google.be
💡 Begrijp dit In de routetabel zie je twee soorten regels: de default route (0.0.0.0 → gateway) voor al het externe verkeer, en de directe netwerkroute (192.168.112.0/24) voor het lokale subnet dat zonder gateway bereikt wordt.
✔ Verificatie Bij ping moet je 0% packet loss zien. In route -n: wat is het IP van je gateway? (Hint: de regel met bestemming 0.0.0.0)
Deel 2 — NetworkManager met nmcli
nmcli Taak 03
Begrijp het verschil tussen devices en connections
▶

Dit is het belangrijkste concept van het hele hoofdstuk. Voer beide commando's uit en vergelijk.

# Toon alle connections (config-profielen) nmcli connection show nmcli c s # verkort # Toon alle devices (hardware-interfaces) nmcli device status nmcli d
💡 Het kernconcept Device = de hardware (bv. ens160). Connection = een configuratieprofiel (IP, gateway, DNS) dat je aan een device koppelt. Analogie: de device is je smartphone, de connection is je SIM-profiel. Eén device kan meerdere connections hebben — je wisselt met één commando van "Home" (DHCP) naar "Work" (static).
✔ Verificatie Welke connection is gekoppeld aan device ens160? Staat het device op connected?
nmcli Taak 04
Maak een nieuwe statische connection "Verbinding"
▶

Maak op de server een nieuwe connection genaamd Verbinding voor ens160 met IP 192.168.112.50/24, gateway 192.168.112.2 en DNS 8.8.8.8 + 8.8.4.4. (Dit is oefening 3 uit de cursus.)

sudo nmcli connection add type ethernet con-name Verbinding ifname ens160 \ ipv4.addresses 192.168.112.50/24 \ ipv4.gateway 192.168.112.2 \ ipv4.dns "8.8.8.8 8.8.4.4" \ ipv4.method manual # Activeer de connection sudo nmcli connection up Verbinding
⚠ Drie veelgemaakte fouten 1. ipv4.method manual vergeten → device blijft DHCP gebruiken.
2. Vergeten con up te doen → wijziging is nog niet actief.
3. Netmask in verkeerde syntax → gebruik altijd CIDR zoals /24, niet 255.255.255.0 apart.
✔ Verificatie nmcli con show Verbinding | grep ipv4 — controleer adres, gateway en DNS.
ip a show ens160 — heeft het device nu 192.168.112.50?
nmcli Taak 05
Stel autoconnect-voorkeuren in
▶

Zorg dat Verbinding automatisch verbindt bij boot, en dat de oorspronkelijke connection dat niet doet. (Oefening 4.)

# Verbinding krijgt autoconnect aan sudo nmcli connection modify Verbinding connection.autoconnect yes # De oude connection krijgt autoconnect uit (vervang <oude-naam>) sudo nmcli connection modify <oude-naam> connection.autoconnect no
✔ Verificatie nmcli -f connection.autoconnect con show Verbinding moet yes tonen.
Welke is de "oude naam"? Kijk terug naar taak 3: dat was de connection die oorspronkelijk aan ens160 gekoppeld was (vaak ens160 of Wired connection 1).
nmcli Taak 06
Voeg een aangepaste route toe
▶

Voeg een route toe voor het netwerk 10.0.100.0/24 via gateway 192.168.112.200. (Oefening 5.)

sudo nmcli connection modify Verbinding \ +ipv4.routes "10.0.100.0/24 192.168.112.200" sudo nmcli connection up Verbinding
💡 Begrijp dit De + voor ipv4.routes betekent toevoegen aan de bestaande routes in plaats van overschrijven. Zonder + wis je alle bestaande extra routes.
✔ Verificatie ip route show — je ziet nu een regel 10.0.100.0/24 via 192.168.112.200.
nmcli Taak 07
Bewerk een connection interactief en hernoem hem
▶

Oefen de interactieve editor en het hernoemen van connections.

# Snel hernoemen via modify sudo nmcli connection modify Verbinding con-name Verbinding2 # Of via de interactieve editor sudo nmcli connection edit Verbinding2 # In de editor: # print → toon alle eigenschappen # set connection.id NieuweNaam # save # quit
✔ Verificatie nmcli connection show toont de nieuwe naam. Daarna kan je hem verwijderen met sudo nmcli connection delete NieuweNaam als je wil opruimen.
Deel 3 — IP-adressen met ip & nmcli
Tools Taak 08
Voeg tijdelijk een IP toe met ip addr
▶

Met ip addr add voeg je direct een IP toe aan een interface. (Oefening 1.) Let op: dit is tijdelijk en verdwijnt bij reboot — anders dan nmcli.

sudo ip addr add 192.168.1.1/24 dev ens160 # Controleer ip addr show ens160 # Weer verwijderen sudo ip addr del 192.168.1.1/24 dev ens160
💡 ip vs nmcli — belangrijk verschil ip addr add wijzigt de live kernel-config direct, maar slaat niets op → verdwijnt bij reboot. nmcli schrijft naar een persistent connection-profiel → blijft na reboot. Voor productie gebruik je dus altijd nmcli.
✔ Verificatie Na ip addr add toont ip a het tweede adres naast het bestaande. Het /24 komt overeen met netmask 255.255.255.0.
Deel 4 — Netwerk Bonding (Redundantie)
Bond Taak 09
Voeg een tweede netwerkadapter toe en laad de bonding-module
▶

Bonding combineert meerdere fysieke interfaces tot één logische — voor extra snelheid of redundantie. Je hebt minstens 2 adapters nodig.

In VMware: ga naar de instellingen van je server-VM → Add → Network Adapter → Finish → OK. Start de VM op.

# Controleer dat je nu 2 interfaces hebt ip link show # Laad de bonding kernel module sudo modprobe bonding
💡 Bonding-modi active-backup (modus 1): één interface actief, de andere staat klaar als back-up bij uitval → redundantie.
balance-rr / round-robin (modus 0): pakketten worden afwisselend over beide interfaces gestuurd → load balancing.
✔ Verificatie ip link show toont nu ens160 én ens224 (of een gelijkaardige tweede naam).
Bond Taak 10
Maak een active-backup bond met twee slaves
▶

Verwijder eerst de bestaande connection op ens160, maak dan de bond-master aan en koppel beide interfaces als slave. (Gebaseerd op de cursusvoorbeelden en oefening 7.)

# 1. Verwijder bestaande connection op ens160 sudo nmcli connection delete ens160 # 2. Maak de bond-master (active-backup) sudo nmcli connection add type bond con-name PXL-bond ifname Master-bond mode active-backup # 3. Koppel beide interfaces als slave sudo nmcli connection add type ethernet con-name ens160-slave ifname ens160 master Master-bond sudo nmcli connection add type ethernet con-name ens224-slave ifname ens224 master Master-bond # 4. Geef de bond een statisch IP sudo nmcli connection modify PXL-bond \ ipv4.addresses 192.168.112.100/24 \ ipv4.gateway 192.168.112.2 \ ipv4.dns 192.168.112.2 \ ipv4.method manual # 5. Breng alles online sudo nmcli connection down PXL-bond && sudo nmcli connection up PXL-bond sudo nmcli connection up ens160-slave sudo nmcli connection up ens224-slave
✔ Verificatie Zie volgende taak — je controleert de bond-status via /proc/net/bonding/.
Bond Taak 11
Controleer de bond en simuleer een failover
▶

Bekijk de status van de bond, schakel dan de actieve slave uit en zie hoe de back-up het overneemt — dit is de hele bedoeling van active-backup.

# Toon de bond-status: welke slave is actief? cat /proc/net/bonding/Master-bond # Schakel de actieve slave uit (failover trigger) sudo nmcli device disconnect ens160 # Check opnieuw: de active slave is nu ens224 cat /proc/net/bonding/Master-bond
✔ Verificatie Voor de failover: Currently Active Slave: ens160. Na het uitschakelen: Currently Active Slave: ens224. De bond bleef werken zonder onderbreking — dat is redundantie.
⚠ VMware-beperking: na een failover kan ping falen met "Naam of dienst niet bekend". VMware NAT kan maar één MAC per VM NAT-ten. Simuleer correct gedrag door de nieuwe actieve interface kort te herverbinden:
sudo nmcli device disconnect ens224 && sudo nmcli device connect ens224
Op echte hardware met RHEL werkt dit gewoon.
Bond Taak 12
Maak een round-robin bond (load balancing)
▶

Maak nu een bond in balance-rr modus, waar pakketten afwisselend over beide interfaces gaan. (Oefening 6.) Verwijder eerst de vorige bond als die er nog is.

Het enige verschil met taak 10 is de mode. Voor round-robin gebruik je mode balance-rr (of mode 0) bij het aanmaken van de bond-master.
sudo nmcli connection add type bond con-name rr-bond ifname bond0 mode balance-rr sudo nmcli connection add type ethernet con-name s1 ifname ens160 master bond0 sudo nmcli connection add type ethernet con-name s2 ifname ens224 master bond0 sudo nmcli connection modify rr-bond ipv4.addresses 192.168.112.100/24 \ ipv4.gateway 192.168.112.2 ipv4.dns 192.168.112.2 ipv4.method manual sudo nmcli connection up rr-bond sudo nmcli connection up s1 sudo nmcli connection up s2
✔ Verificatie cat /proc/net/bonding/bond0 moet Bonding Mode: load balancing (round-robin) tonen.
Debug Taak 13
Debug een kapotte bond-configuratie
▶

Een collega maakte deze config, maar er is geen netwerkverbinding. Bekijk de commando's en zoek de fout. (Oefening 9 — een echte troubleshooting-vraag.)

# De problematische config: nmcli connection add type bond ifname bond0 mode active-backup nmcli connection add type ethernet ifname ens160 master bond0 nmcli connection add type ethernet ifname ens224 master bond0 nmcli connection modify bond0 ipv4.method manual \ ipv4.addresses 192.168.50.10/24 ipv4.gateway 192.168.50.1 nmcli connection up bond0

Gebruik deze tools om te debuggen:

nmcli connection show cat /proc/net/bonding/bond0 ip addr
Denk na: na het aanmaken van de bond en de slaves — werden de slave-connections wel geactiveerd? En past de gateway 192.168.50.1 bij jouw werkelijke netwerk (je NAT is 192.168.112.0)?

Twee problemen:

1. De slaves werden nooit geactiveerd. Er is alleen connection up bond0 gedaan, maar de slave-connections (ens160 en ens224) zijn niet ge-upt, dus de bond heeft geen actieve members.

2. De gateway klopt niet met het werkelijke netwerk. 192.168.50.1 bestaat niet in jouw NAT-omgeving (die is 192.168.112.0/24).

# Herstel: activeer de slaves sudo nmcli connection up ens160 sudo nmcli connection up ens224 # Corrigeer adres + gateway naar het juiste netwerk sudo nmcli connection modify bond0 ipv4.addresses 192.168.112.100/24 ipv4.gateway 192.168.112.2 sudo nmcli connection up bond0 # Verifieer cat /proc/net/bonding/bond0 # slaves moeten nu zichtbaar zijn
Deel 5 — Server als Router (PAT / Masquerading)
PAT Taak 14
Configureer beide interfaces op server en client
▶

De server krijgt twee rollen: ens160 = extern (internet via NAT), ens224 = intern (services + client). Eerst de IP's.

Op de server:

# External: ens160 → internet sudo nmcli connection add type ethernet con-name External ifname ens160 \ ipv4.addresses 192.168.112.100/24 ipv4.gateway 192.168.112.2 \ ipv4.dns 192.168.112.2 ipv4.method manual sudo nmcli connection up External # Internal: ens224 → intern netwerk (GEEN gateway!) sudo nmcli connection add type ethernet con-name Internal ifname ens224 \ ipv4.addresses 10.10.10.1/24 ipv4.method manual sudo nmcli connection up Internal

Op de client:

sudo nmcli connection add type ethernet con-name Connection ifname ens160 \ ipv4.addresses 10.10.10.10/24 ipv4.gateway 10.10.10.1 \ ipv4.dns 8.8.8.8 ipv4.method manual sudo nmcli connection up Connection
💡 Waarom geen gateway op Internal? Een interface mag maar één default gateway hebben. De server stuurt al zijn internetverkeer via ens160 (External). De interne interface ens224 is het eindpunt van het privé-netwerk, niet een doorgang naar buiten — daarom geen gateway daar.
✔ Verificatie Op de client: ping -c 4 10.10.10.1 moet werken (client bereikt de server). Internet werkt nog niet — dat regelen we in de volgende taken.
PAT Taak 15
Wijs firewall-zones toe en schakel masquerading in
▶

Op de server: koppel de externe interface aan de external zone (streng) en de interne aan internal (vertrouwd). Masquerading laat de server interne IP's "verbergen" achter zijn eigen externe IP.

# Interfaces aan zones koppelen sudo firewall-cmd --change-interface=ens160 --zone=external --permanent sudo firewall-cmd --change-interface=ens224 --zone=internal --permanent sudo firewall-cmd --complete-reload # Standaard zone + DNS toestaan op intern sudo firewall-cmd --set-default-zone=internal sudo firewall-cmd --zone=internal --add-service=dns --permanent # Masquerading expliciet aanzetten op external sudo firewall-cmd --permanent --zone=external --add-masquerade sudo systemctl restart firewalld
💡 Wat is PAT / masquerading? Port Address Translation laat meerdere privé-IP's (bv. de client op 10.10.10.10) naar buiten gaan via één publiek IP (de server op 192.168.112.100), waarbij poortnummers de verbindingen uit elkaar houden. Dit is precies wat je thuisrouter ook doet.
✔ Verificatie sudo firewall-cmd --list-all --zone=external — je ziet masquerade: yes en interface ens160. Internet op de client werkt nog steeds niet — er ontbreekt een forwarding policy (volgende taak).
PAT Taak 16
Voeg een forwarding policy toe en test internet op de client
▶

De laatste stap: expliciet toestaan dat verkeer van internal naar external mag doorstromen. Daarna heeft de client internet via de server.

# Maak een policy van internal → external sudo firewall-cmd --permanent --new-policy policy_int_to_ext sudo firewall-cmd --permanent --policy policy_int_to_ext --add-ingress-zone internal sudo firewall-cmd --permanent --policy policy_int_to_ext --add-egress-zone external sudo firewall-cmd --permanent --policy policy_int_to_ext --set-priority 100 sudo firewall-cmd --permanent --policy policy_int_to_ext --set-target ACCEPT sudo systemctl restart firewalld
✔ Verificatie — op de CLIENT ping -c 4 10.10.10.1 → bereikt de server (gateway).
ping -c 4 www.google.be → werkt nu via de server als router!
Geen internet op de client? Loop deze checklist af:
— Default gateway op client correct? ip route show default moet via 10.10.10.1 gaan.
— DNS ingesteld? cat /etc/resolv.conf op de client.
— Op de server: staat ens160 op UP? ip link show ens160
— Zones correct? sudo firewall-cmd --list-all --zone=external
