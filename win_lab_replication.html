Theorie Replicatie
Theorie 01
Multi-master replicatie begrijpen
theorie
›

In Active Directory kan elke DC wijzigingen doorvoeren. Dit heet multi-master replicatie — er is geen single primary server nodig.

Hoe werkt het?Elke wijziging op een DC wordt lokaal opgeslagen in NTDS.dit. Daarna stuurt de DC een replicatieverzoek naar zijn partners (pull-model). DC's gebruiken USN (Update Sequence Numbers) om bij te houden welke wijzigingen nog gesynchroniseerd moeten worden.
TermUitleg
USNUpdate Sequence Number — uniek volgnummer per wijziging
GUIDGlobale unieke ID van een DC
KCCKnowledge Consistency Checker — bepaalt replicatietopologie automatisch
repadminCLI-tool voor replicatiebeheer en -diagnose
ℹ Info — Standaard repliceert AD binnen een site elke 15 seconden, tussen sites elke 15 minuten (configureerbaar).
Theorie 02
Global Catalog Server en FSMO-rollen kennen
theorie
›

De Global Catalog (GC) is een DC die een gedeeltelijke kopie bijhoudt van alle objecten in het volledige AD-forest.

  • Bevat de meest gezochte attributen van elk object
  • Noodzakelijk voor Universal Group membership in multi-domein forests
  • Standaard is de eerste DC automatisch GC-server

FSMO-rollen (Flexible Single Master Operations) — 5 speciale rollen die slechts op één DC tegelijk mogen staan:

FSMO-rolFunctieScope
Schema MasterWijzigingen aan AD-schemaForest
Domain Naming MasterDomeinen toevoegen/verwijderenForest
PDC EmulatorTijdsynchronisatie, wachtwoord policiesDomein
RID MasterUnieke SIDs toewijzen aan objectenDomein
Infrastructure MasterVerwijzingen naar objecten in andere domeinenDomein
netdom query fsmo

Toont welke DC welke FSMO-rollen heeft.

AD Failover configureren
Taak 03
Tweede Domain Controller toevoegen (AD-failover)
installatieconfig
›

Een tweede DC toevoegen zorgt voor redundantie — als DC1 uitvalt, blijft het domein beschikbaar.

Vereisten voor DC2:

  • Nieuwe Windows Server VM met naam WINADV-DC2
  • Statisch IP in hetzelfde subnet
  • DNS verwijst naar DC1

Joinen aan bestaand domein:

  • Installeer AD DS-rol op DC2 (zelfde stappen als Lab 02)
  • Promoveer: kies "Add a domain controller to an existing domain"
  • Domein: pxldigital.local
  • Gebruik domain admin credentials
  • Vink aan: DNS Server, Global Catalog
  • DSRM-wachtwoord instellen → Install
✔ VerificatieNa herstart: controleer in ADUC of DC2 zichtbaar is onder Domain Controllers.
Theorie 04
Replicatie verifiëren met repadmin
testdebug
›

Gebruik repadmin om de replicatiestatus te controleren.

repadmin /replsummary

Geeft een samenvatting van de replicatiestatus per DC.

repadmin /showrepl

Toont gedetailleerde replicatiepartners en laatste synchronisatietijden.

repadmin /syncall /AdeP

Forceert onmiddellijke replicatie van alle partities naar alle partners.

✔ VerificatieGeen fouten in de output? Replicatie werkt correct. Maak een testgebruiker aan op DC1 en controleer of die na synchronisatie ook op DC2 zichtbaar is.
AD Delegation
Taak 05
Delegatie instellen op een OU
config
›

Via delegatie geef je een gebruiker beperkte beheertaken in AD, zonder volledige Domain Admin-rechten.

Voorbeelden:

  • Helpdesk mag wachtwoorden resetten in OU Studenten
  • Junior admin mag computers joinen aan het domein
  • Teamleider mag users aanmaken in zijn OU

Delegatie instellen:

  • In ADUC: rechtsklik op de OU waarop je wil delegeren → "Delegate Control"
  • Klik Next → Add → selecteer de gebruiker of groep
  • Kies een vooraf gedefinieerde taak (bijv. "Reset user passwords")
  • Of kies "Create a custom task" voor specifieke controle
  • Finish
⚠ Let op — Delegatie werkt op OU-niveau. Gebruikers buiten die OU vallen niet onder de gedelegeerde rechten.
ℹ Info — Delegatie lost het probleem op van "te veel Domain Admins" — principe van least privilege.
