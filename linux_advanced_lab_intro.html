PXL Linux Advanced · Intro Chapter Lab

Server Administratie Basics

Hands-on labo op basis van de cursusinhoud: SSH & sleutels, bestandsoverdracht, systemd services en runlevels. Werk de taken in volgorde door op je RHEL/Rocky Linux VM.

📋 Scenario

Je bent systeembeheerder van een kleine organisatie. Je hebt twee Linux VMs: een client (jouw werkplek) en een server. Voordat je SSH en services aanpakt, zorg je eerst dat beide machines een correcte basisopzet hebben — de juiste hostnaam, up-to-date repos en een werkende netwerkconfiguratie. Alles wat je daarna doet volgt de 5-stappen aanpak uit de cursus: installeer → configureer → start → beveilig → monitor.

Vereiste: je hebt twee RHEL VM's met elk een clean-install snapshot. Heb je die nog niet, zie cursushoofdstuk 1 (Installatie & Virtualisatie) en keer terug als beide machines starten.

🗺 Oriëntatie Essentials → Advanced: wat verandert er? klik om uit te vouwen

Je komt van Linux Essentials op Ubuntu. Linux Advanced gebruikt Red Hat Enterprise Linux (RHEL) — de industriestandaard op bedrijfsservers. De concepten zijn identiek, alleen de tools verschillen. Hieronder de vier grootste wijzigingen die je nu meteen moet kennen.

1 · Package manager
Ubuntu
RHEL
apt updatednf check-update apt install PKGdnf install PKG apt upgradednf update apt remove PKGdnf remove PKG

Concept identiek — alleen de naam verschilt. dnf staat voor Dandified YUM.

2 · Netwerkconfiguratie
Ubuntu
RHEL
ifconfigip addr show netplannmcli /etc/network/interfaces/etc/NetworkManager/

nmcli is de cli voor NetworkManager — alles wat je in Lab 02 nodig hebt.

3 · Services (systemd)

Goed nieuws: systemd is identiek op Ubuntu en RHEL. systemctl start/stop/enable/status werkt exact hetzelfde. Wat nieuw is: je leert de internals beter kennen — targets, wants, unit-bestanden schrijven.

4 · Beveiliging: nieuw in Advanced

SELinux — Mandatory Access Control, standaard aan op RHEL. Als iets niet werkt, is 80% van de tijd SELinux de oorzaak. nftables — vervangt iptables als low-level firewall. Kom je dit pas tegen in Lab 08 & 09.

💡 Onthoud: de concepten (package manager, service manager, netwerkconfiguratie) zijn hetzelfde. Enkel de commando's en tools zijn enterprise-grade varianten. Na een week voel je het verschil niet meer.

Deel 0 — Startklaar maken
Setup Taak 00a
Verifieer je startpositie: snapshot & netwerk OK
▶

Voordat je iets configureert, check je of beide VM's in de juiste begintoestand staan. Start vanuit je clean-install snapshot zodat je altijd kan terugkeren als iets misloopt.

Waarom snapshots? Een snapshot is een "foto" van de VM op dat moment. Gaat er iets mis verderop in het lab, dan kan je gewoon terugkeren naar dit punt zonder alles opnieuw te installeren. Je lector heeft al gevraagd dat je die klaar hebt — dit is waarom.

# Op BEIDE machines: controleer of je netwerk werkt ip addr show # Je moet minstens een lo (loopback) en een ens/eth interface zien met een IP # Ping naar buiten om te controleren of je internetverbinding werkt ping -c 3 8.8.8.8 # Als dit mislukt: check je VM-netwerkinstellingen (NAT aan?)

Geen IP op je interface? Probeer nmcli device status — staat de interface op "disconnected"? Dan nmcli device connect <interfacenaam>. In VMWare moet de VM op NAT of Bridged staan voor internettoegang.

Setup Taak 00b
Stel de hostnamen in: serverXX en clientXX
▶

Een hostnaam is de naam van je machine op het netwerk. Zonder correcte hostnamen weet je later niet meer welke terminal bij welke machine hoort — zeker als je meerdere SSH-sessies open hebt.

Vervang XX door je eigen servernummer (vraag het aan je lector als je het niet weet).

# Op de SERVER (vervang XX door jouw nummer, bijv. 01): sudo hostnamectl hostname serverXX # Verifieer: hostnamectl status # Op de CLIENT: sudo hostnamectl hostname clientXX hostnamectl status # De nieuwe hostnaam is zichtbaar na een nieuwe login of: exec bash

Wat doet hostnamectl? Het commando past drie dingen tegelijk aan: de kernel-hostnaam (tijdelijk), de "pretty" naam (leesbaar) en de statische naam in /etc/hostname (blijft na reboot). Vroeger moest je dat bestand manueel aanpassen — hostnamectl is de moderne manier.

Zie je de nieuwe hostnaam nog niet in je prompt? Dat is normaal — de shell toont de hostnaam van het moment dat je inlogde. Log opnieuw in of gebruik exec bash om de shell te herladen.

Setup Taak 00c
Update de packages op de server (dnf update)
▶

Een verse installatie heeft bijna altijd verouderde packages. Updaten zorgt dat je de nieuwste versies en beveiligingspatches hebt — en dat je repos bereikbaar zijn. Dit is altijd de eerste actie na een clean install.

Kom je van Ubuntu/Debian? In RHEL gebruik je dnf in plaats van apt. Het concept is identiek: een package manager die software installeert vanuit online repositories. Alleen de commando's verschillen (zie ook de oriëntatiekaart hierboven).

# Op de SERVER: controleer eerst welke updates beschikbaar zijn sudo dnf check-update # Installeer alle updates (-y bevestigt automatisch) sudo dnf update -y # Controleer of alles in orde is — geen errors? sudo dnf check # Facultatief: herstart als er een kernel-update was # sudo reboot now

Krijg je een fout zoals "No repositories configured" of "Cannot download repomd.xml"? Dan heeft de VM geen verbinding met het internet. Ga terug naar taak 00a en fix het netwerk eerst. De repos van RHEL vereisen ook dat je VM gekoppeld is aan je Red Hat-account (werd ingesteld tijdens installatie).

Deel 1 — SSH & Sleutels
SSH Taak 01
Log in op de server via SSH met een wachtwoord
▶

Maak vanuit je client een SSH-verbinding met de server (gebruiker: student). Vervang <server-ip> door het werkelijke IP-adres van je server.

ssh student@<server-ip>

Je wordt gevraagd om een wachtwoord. Na het inloggen zie je de prompt van de server. Typ exit om terug te keren naar de client.

✔ Verificatie Wanneer ingelogd, controleer je op welk systeem je zit:
hostname
De output moet de hostnaam van de server tonen, niet van de client.
SSH Taak 02
Voer een commando uit op de server zonder in te loggen
▶

SSH laat je toe commando's op de server uit te voeren zonder eerst een interactieve sessie te openen. Toon de inhoud van /etc/system-release op de server vanuit de client.

ssh student@<server-ip> cat /etc/system-release

Je zou iets moeten zien als Rocky Linux release 9.x of gelijkaardig.

✔ Verificatie De output wordt afgedrukt in je clientterminal, zonder dat je op de server inlogt. Handig voor scripting en beheer op afstand!
SSH Taak 03
Genereer een SSH-sleutelpaar
▶

Op de client: genereer een RSA sleutelpaar van 4096 bits. Druk twee keer Enter om geen wachtwoordzin in te stellen.

ssh-keygen -t rsa -b 4096

Dit maakt twee bestanden aan in ~/.ssh/:

~/.ssh/id_rsa # Privésleutel — NOOIT delen! ~/.ssh/id_rsa.pub # Publieke sleutel — mag je verspreiden
✔ Verificatie ls -la ~/.ssh/
Je ziet beide bestanden. De privésleutel heeft rechten -rw------- (600). De publieke -rw-r--r-- (644). Vraag jezelf af: waarom is die scheiding in rechten belangrijk?
SSH Taak 04
Kopieer de publieke sleutel naar de server
▶

Gebruik ssh-copy-id om je publieke sleutel op de server te plaatsen. Je moet dit eenmalig doen met je wachtwoord.

ssh-copy-id student@<server-ip>

Dit voegt je publieke sleutel toe aan ~/.ssh/authorized_keys op de server.

✔ Verificatie Log in zonder wachtwoord:
ssh student@<server-ip>
Je moet nu direct inloggen zonder wachtwoordprompt. Kijk ook even op de server zelf:
cat ~/.ssh/authorized_keys
Werkt ssh-copy-id niet? Controleer of de .ssh directory bestaat op de server: ssh student@server "mkdir -p ~/.ssh && chmod 700 ~/.ssh". Op Windows in PowerShell moet je handmatig de sleutel toevoegen — zie de cursus.
Security Taak 05
Schakel root SSH-login uit op de server
▶

Op de server: pas de SSH-configuratie aan zodat root niet rechtstreeks kan inloggen via SSH. Dit is een fundamentele beveiligingsmaatregel.

sudo nano /etc/ssh/sshd_config

Zoek de regel PermitRootLogin en verander ze naar:

PermitRootLogin no

Herstart de SSH-service zodat de wijziging actief wordt:

sudo systemctl restart sshd
✔ Verificatie Probeer vanaf de client in te loggen als root:
ssh root@<server-ip>
Je zou Permission denied moeten krijgen.
Zorg eerst dat je als student kan inloggen met je sleutel (taak 4) voordat je root uitschakelt. Anders sluit je jezelf buiten!
Deel 2 — Bestandsoverdracht
Files Taak 06
Kopieer een bestand naar de server met scp
▶

Maak op de client een testbestand aan en kopieer het naar de server met scp. De timestamps worden niet bewaard bij scp.

touch testbestand.txt scp testbestand.txt student@<server-ip>:/home/student/
✔ Verificatie Controleer op de server:
ssh student@<server-ip> ls -la ~/testbestand.txt
Noteer de timestamp. Die is de huidige tijd, niet de aanmaaktijd op de client.
Files Taak 07
Synchroniseer een map met rsync en behoud timestamps
▶

Kopieer de map /usr/share/sounds van de server naar /tmp/sounds-backup op de client met rsync. De -a vlag behoudt alles: rechten, eigenaar, tijdstempels, symlinks.

rsync -avz student@<server-ip>:/usr/share/sounds/ /tmp/sounds-backup/
✔ Verificatie Vergelijk de timestamps:
ls -la /tmp/sounds-backup/
De tijdstempels moeten overeenkomen met die op de server. Voer rsync nu een tweede keer uit — wat merk je?
rsync is slim: bij een tweede run worden alleen gewijzigde bestanden overgedragen. Dit is het grote voordeel tegenover scp voor back-ups. De -v vlag toont je wat er wordt overgedragen.
Files Taak 08
Gebruik sftp interactief om bestanden te beheren
▶

Open een interactieve SFTP-sessie met de server. SFTP gedraagt zich als een FTP-client maar is volledig versleuteld via SSH.

sftp student@<server-ip>

Probeer nu de volgende commando's binnen de sftp-shell:

lls # lokale bestanden tonen ls # bestanden op de server tonen mkdir /home/student/upload-test put testbestand.txt # upload naar server ls # controleer of het er staat get testbestand.txt /tmp/download-test.txt # download van server quit
✔ Verificatie Check lokaal: ls /tmp/download-test.txt
Check op server: ssh student@<server-ip> ls ~/upload-test/
Deel 3 — Systemd & Services
Systemd Taak 09
Controleer welk init-systeem de server gebruikt
▶

Op de server: bevestig dat systemd het init-systeem is. PID 1 is altijd het init-systeem — op moderne Linux is dat systemd.

ps -e | head

Je kan ook direct de naam opvragen:

ps -p 1 -o comm=
✔ Verificatie De output toont systemd als PID 1. Probeer ook:
systemctl --version
Systemd Taak 10
Installeer en start de cups (print) service
▶

Op de server: volg de 5-stappen methode voor CUPS. Dit is een printserver die we gebruiken als oefenobject omdat hij onschadelijk is.

# Stap 1: Installeer sudo dnf install cups -y # Stap 2: Controleer de configuratie (bekijk even, niet aanpassen) cat /etc/cups/cupsd.conf | head -30 # Stap 3: Start de service sudo systemctl start cups # Stap 3b: Enable zodat hij herstart na reboot sudo systemctl enable cups # Stap 5: Controleer de status sudo systemctl status cups
✔ Verificatie In de status output zie je:
Active: active (running) — service draait nu
Loaded: ... enabled — start automatisch bij reboot
Systemd Taak 11
Stop, herstart en herlaad services
▶

Oefen de verschillende manieren om services te beheren. Let op het verschil tussen restart en reload!

# Stop de service tijdelijk sudo systemctl stop cups sudo systemctl status cups # Toont: inactive (dead) # Start hem opnieuw op sudo systemctl start cups # Herstart (= stop + start in één) sudo systemctl restart cups # Reload: herlees configuratie ZONDER de service te stoppen # (niet alle services ondersteunen dit) sudo systemctl reload sshd # Conditioneel herstart: alleen als de service al draait sudo systemctl condrestart cups
✔ Verificatie Begrijp het verschil: waarom is reload beter dan restart voor een productiewebserver?
Systemd Taak 12
Toon alle actieve services en units
▶

Bekijk welke services actief zijn op het systeem. Dit is je dagelijkse tool om een overzicht te krijgen.

# Alle actieve service units systemctl list-units --type=service # Alle actieve target units (runlevel-equivalenten) systemctl list-units --type=target # Filter met grep systemctl list-units | grep .service | grep running # Toon gefaalde services (nuttig bij problemen!) systemctl --failed
✔ Verificatie Zie je cups.service in de lijst? Zie je sshd.service? Hoeveel services draaien er in totaal?
Deel 4 — Runlevels & Targets
Systemd Taak 13
Bekijk het huidige runlevel en de standaard target
▶

Systemd gebruikt targets in plaats van runlevels. Maar voor backward compatibiliteit werkt runlevel nog steeds.

# Oud SysVinit manier (werkt nog steeds) runlevel # Moderne systemd manier systemctl get-default # Bekijk de symbolische links die de compat. verzorgen ls -l /lib/systemd/system/runlevel*.target
✔ Verificatie runlevel toont iets als N 5 (vorig + huidig runlevel).
systemctl get-default toont graphical.target of multi-user.target.
Kijk naar de symlinks: zie je hoe runlevel3.target → multi-user.target wijst?
Systemd Taak 14
Wissel de standaard target naar niet-grafisch en terug
▶

Op een server zonder scherm wil je multi-user.target als standaard (geen GUI = minder resources). Oefen het wisselen — dit hoef je niet te rebooten om te testen.

# Zet standaard op niet-grafisch (runlevel 3 equivalent) sudo systemctl set-default multi-user.target # Controleer systemctl get-default # Schakel direct (zonder reboot) naar multi-user sudo systemctl isolate multi-user.target # Zet terug naar grafisch (runlevel 5 equivalent) sudo systemctl set-default graphical.target sudo systemctl isolate graphical.target
✔ Verificatie Na isolate multi-user.target op een machine met GUI: de grafische omgeving verdwijnt!
Opgelet: Doe dit alleen als je via SSH verbonden bent, anders verlies je tijdelijk je interface.
set-default wijzigt wat er bij de volgende reboot gestart wordt.
isolate schakelt nu onmiddellijk over, zonder reboot. Gebruik isolate enkel bewust!
Deel 5 — Verkenning (Uitdaging)
Uitdaging Taak 15
Maak een backup van /etc via rsync over SSH
▶

Combineer alles wat je geleerd hebt: gebruik rsync over SSH om de /etc directory van de server te back-uppen naar /tmp/etc-backup op de client. Zorg voor compressie en delta-transfers. Dit is een realistische back-uptaak.

Denk na over:
— rsync van server naar client: de bron is student@server:/etc/
— Welke vlaggen gebruik je? -a voor archive mode, -v voor verbose, -z voor compressie
— Vergeet de trailing slash niet bij de bronmap!
rsync -avz student@<server-ip>:/etc/ /tmp/etc-backup/

Voer het daarna een tweede keer uit. Omdat er niets veranderd is, zou rsync vrijwel niets over te dragen hebben. Dat is de kracht van delta-transfers!

✔ Verificatie ls /tmp/etc-backup/ — je ziet de volledige /etc structuur op je client.
diff /tmp/etc-backup/hostname <(ssh student@<server-ip> cat /etc/hostname) — bestanden moeten identiek zijn.
